# Decision

* [Body tokens and pluginfinity links are built per target](body-tokens-and-links-are-built-per-target.md) - Skill and agent bodies name tools, agents, skills and the plugin root through explicit {{kind name}} tokens, and other components through inline pluginfinity:// links, which each target spells from its own data; anything a target cannot spell fails the build, with host blocks as the escape hatch.
* [Build notes also report hook matchers, ignored hook output and omitted monitors](build-notes-cover-hooks-and-monitors.md) - The info-level build notes grow from four kinds to seven, adding hook-matcher-runtime, hook-output-ignored and monitor-omitted, so a hook or monitor a host cannot honour as written is reported instead of silently weaker.
* [Build notes report what a target drops, degrades or omits](build-notes-report-dropped-fields.md) - Every build and validate reports, at info level and without failing, each frontmatter or server field a target drops or degrades, each tool it cannot name and each hook event it omits, replacing the rule that a dropped field is silent.
* [Built plugins carry no Node dependencies](plugins-carry-no-node-dependencies.md) - For the first release, a plugin pluginfinity builds is markdown, JSON and bash scripts only, with no Node runtime dependencies to install.
* [Claude Code's MCP and LSP servers go inline in plugin.json](claude-servers-go-inline-in-the-manifest.md) - The claude target writes its MCP and LSP servers inline under mcpServers and lspServers in .claude-plugin/plugin.json instead of a root .mcp.json and .lsp.json, because repositories conventionally gitignore .mcp.json and a committed build then ships no MCP server; Copilot keeps its server files.
* [Claude Code's names are the source vocabulary](claude-code-names-are-the-source-vocabulary.md) - Plugin source writes hook events, tool names and skill and agent frontmatter fields with Claude Code's names, and each target maps them; per-host additions go in a targets block.
* [Facts about a hook entry travel to its script as environment variables](entry-facts-travel-as-env.md) - The build gives each hook entry its event, its fail policy and, where the host ignores the matcher, its matcher through PLUGINFINITY\_\* variables, in exec-form env on Claude Code script entries and the env field on Copilot.
* [Hooks fail open on both hosts](hooks-fail-open.md) - A hook script that fails exits 0 with no response on Claude Code and Copilot alike, unless it opted into failing closed with hook\_fail\_closed.
* [Hooks, servers, monitors and scripts share one logging standard](one-logging-standard.md) - One log.sh, injected into every target, writes error.log always and debug.log when PLUGINFINITY\_DEBUG=1, in one line format under one per-plugin state directory, replacing the per-component log files and PLUGINFINITY\_HOOK\_DEBUG.
* [Monitors are a first-class component](monitors-are-a-component.md) - A plugin declares background monitors in the config, the build writes Claude Code's monitors file and ships their scripts and the monitor library, and a host with no monitors drops them with a monitor-omitted note.
* [Server launchers ship by discovery and files, beside an injected server library](server-launchers-ship-by-discovery-and-files.md) - A build ships every plugin file a target's MCP and LSP servers name after ${PLUGIN\_ROOT}/, plus what the files key lists, and writes a POSIX sh server library to lib/pluginfinity/ with PLUGINFINITY\_\* variables in each local server's env.
* [Targets are data plus a closed set of named formats](targets-are-data-plus-named-formats.md) - A target is a decoded description of tables and facts, and where a host's output is structural it names a format literal whose single encoder the engine owns.
* [The copilot target emits Agent Plugins 1.0](copilot-target-emits-agent-plugins.md) - pluginfinity's copilot target writes plugins in the Agent Plugins 1.0 (Open Plugin Spec) format, not Copilot CLI's legacy plugin format.
* [The hook library is injected at build time](hook-library-is-build-injected.md) - The bash helper library for hook scripts ships inside the engine, and build writes it into every target that has hooks, with a generated host.sh that names the host at run time.
* [The tool is named pluginfinity](pluginfinity-name.md) - pluginfinity names the CLI, its carrier package, its bin and its config file, with the layer packages under the @pluginfinity npm scope.
* [pluginfinity is a CLI application in its own repository](pluginfinity-is-a-cli-application.md) - The single-source plugin builder ships as a standalone @effected/cli application with a companion plugin that succeeds plugin-bot, not as an @effected kit package developed inside the bot marketplace repository.
* [pluginfinity ships as a carrier package over scoped layer packages](pluginfinity-ships-as-a-carrier-package.md) - The CLI is split into @pluginfinity/core, @pluginfinity/targets, @pluginfinity/engine and @pluginfinity/cli, with the unscoped pluginfinity package as the carrier that owns the bin; only what the carrier exports is supported surface.
